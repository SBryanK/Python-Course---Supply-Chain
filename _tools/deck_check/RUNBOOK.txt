PATCHES TO OUR SKILL COPY (only _tools/ppt_maker/ppt-maker/scripts/render.py, 2 small changes)
  a) PROFILE no longer ~/.cache (blocked by the sandbox). It is now:
       _DEFAULT_PROFILE = Path(__file__).resolve().parents[3] / "deck_check" / "lo_profile"
       PROFILE = Path(os.environ.get("PPT_MAKER_PROFILE") or _DEFAULT_PROFILE).expanduser().resolve()
  b) The LibreOffice profile URL now uses PROFILE.as_uri() instead of
     f"file://{PROFILE}". Reason: this repo path contains spaces, and soffice aborts
     with an uncaught com::sun::star::uno::RuntimeException (SIGABRT) when the
     -env:UserInstallation file URL has raw spaces. as_uri() percent-encodes them.
  Do not revert either change for later decks.

REMAINING WORKAROUNDS FOR ALL LATER DECKS
  - Keep using the patched render.py for the PDF; prefer it over the --pdf option embedded
    in a new_deck.py build script. That option runs soffice with no profile override and
    no font check. It did happen to produce a valid PDF with Proxima Nova embedded here,
    but the default LibreOffice profile (~/Library/Application Support/LibreOffice) is not
    writable in this sandbox, so it is not the reliable route. render.py also prints the
    font-substitution check and makes the page images and contact sheet.
  - Keep decks and build scripts inside the repo. Rendering a pptx outside the workspace
    would need to write a LibreOffice profile outside the workspace, which is blocked.
  - PATH must include /opt/homebrew/bin (soffice, pdftoppm, pdffonts); HOME/XDG overrides
    are not needed for render.py. Set MPLCONFIGDIR only when a build uses matplotlib.
  - Proxima Nova is found under /System/Library/AssetsV2/com_apple_MobileAsset_Font8 and is
    embedded. Montserrat in ~/Library/Fonts is available as the fallback if ever needed.
  - No NUS logo or NUS content was used anywhere (private course).
